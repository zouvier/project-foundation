# Audit responses through v0.1.2

The independent v0.1.0 audit found false-green acceptance paths despite the original 82 passing cases. The fixes below address those reproductions. The TypeScript fresh-agent pilot supplied the additional source-lineage finding. See [verification](verification.md) for the final run and [pilot evidence](pilot.md) for the separate v0.1.0 usability results.

| Finding | Change | Regression evidence |
| --- | --- | --- |
| F1: tests can corrupt untracked source after type checking while check passes | The input snapshot covers tracked and untracked working files, additions/deletions, modes and staging. Only explicit root dependency/output paths and `.project/cache` are omitted; tracked files are included even there. | Each profile rewrites, creates and deletes untracked source during a test; the first check must fail after the mutation actually executes. |
| F2: collection-only/all-skipped runs pass; valid native filenames rejected | Canonical tests sanitize inherited runner options, clear pytest addopts, use native discovery inside `tests/`, and require actual passing cases in a fresh JSON/JUnit report. Vitest supplies human and JSON reporters together. | Failing test under inherited collect-only/name filters; all-skipped, empty and malformed reports; native `*.spec.ts` and `*_test.py`; mixed skipped/passing native runs. |
| F3: production npm environment omits development tools yet records readiness | Bootstrap explicitly includes dev/optional dependencies, normalizes relevant installer environment, and verifies executable tools/imports before writing local readiness state. | Production/omit-dev environment still produces a working doctor and check after bootstrap. |
| F4: accepted names collide with locked distributions | Generation rejects normalized names from the actual Python/npm lock graphs, standard-library names and relevant Python import aliases. | Every syntactically valid locked name is tested, including pydantic, starlette, anyio, pydantic-core and typing-extensions. |

| F7: documented relative source breaks updates from the destination | The README uses a quoted absolute source path; generated identity checks reject relative local source provenance. Built-preview instructions distinguish `dist/` from the dev server. | Executes the documented copy statement, then updates from inside the generated repository without editing lineage. Also upgrades actual v0.1.0 projects with valid absolute sources to the new candidate. |

The receipt and native reports are consistency evidence, not signed attestations. Mutation checks detect final differences; they do not prevent writes or prove honest behavior by arbitrary project code. A partial or forged history still needs human review. Root caches/output exclusions are intentional; tests should write temporary artifacts under `.project/cache`.

Projects generated by the defective v0.1.0 relative-source recipe need a controlled migration against their real source. This release does not silently rewrite their answers or modify the completed pilot projects. The new recipe and absolute-source upgrade path are tested separately from any such migration.

The Python identity reader retains a Python 3.9-compatible, dependency-free entry point. It handles the generated plain TOML identity/lock forms and rejects unsupported forms rather than guessing; uv remains the full manifest/dependency validator. This is an explicit v0.1.1 limitation.

## v0.1.1 re-audit: Python environment provenance

The independent re-audit reproduced fixes for all seven original findings, then found two related gaps. Successful test counts did not establish that tests imported the current workspace. The v0.1.2 changes are bounded to this provenance contract; a subsequent bounded independent v0.1.2 re-audit reproduced the repairs and found no new actual blocker.

| Finding | Change | Regression evidence |
| --- | --- | --- |
| R1: `UV_NO_EDITABLE=true` installs a stale wheel; inherited `PYTHONPATH` selects another source copy | Normalize interpreter/install controls, use isolated Python, and require an editable distribution whose direct URL and root import spec identify this repository. Pytest checks loaded root/submodules and collected test module/callable origins in its own process. | First reproduce eight falsely passing tests against a real noneditable wheel or copied sibling source after breaking the current greeting. Canonical doctor/check/test reject the stale installation; explicit bootstrap repairs it. Canonical check/test ignore inherited path redirection and fail on the actual broken source. Also reject pytest-local path redirection, an externally loaded submodule and an external test callable. |
| R2: `UV_PROJECT` installs another project into the current `.venv` while readiness passes | Pin uv's project and working directory explicitly; inherit only reviewed operational uv controls. Validate the installed root package before readiness and every later command. | Real bootstraps with project/directory/combined install overrides prepare the intended editable package without changing sibling inputs. A deliberately misprepared environment fails doctor/check/test without mutation, then explicit bootstrap repairs it. |

The uv policy follows its [documented environment controls](https://docs.astral.sh/uv/reference/environment/) and [project/directory options](https://docs.astral.sh/uv/reference/cli/). Python's [isolated mode](https://docs.python.org/3.13/using/cmdline.html#cmdoption-I) removes inherited import-path/user-site influence. Editable installation checks use the [standard direct URL metadata](https://packaging.python.org/en/latest/specifications/direct-url-data-structure/). The in-process source guard uses [pytest's public plugin hooks](https://docs.pytest.org/en/stable/how-to/writing_plugins.html). These checks inspect actual reported origins; deliberately forged metadata, modules or plugins remain outside the assurance claim.

A focused review found another ordinary stale-source case: `-B` disables bytecode writes but still reads existing caches. A real generated fixture reproduced eight passing tests after `Hello` changed to equal-length `Wrong` with the same timestamp. The final revision uses a fresh nonexistent [bytecode cache prefix](https://docs.python.org/3.13/library/sys.html#sys.pycache_prefix) plus disabled writes for canonical Python execution. The regression preserves the old cache, confirms the raw runner still reads it, and requires canonical check/test to fail on current source without changing tracked files or that cache. The final baseline matrix includes this additional bytecode regression.
