# Design decisions

The foundation template, orchestration implementation and generated projects have distinct responsibilities. They can share a source repository while preserving those boundaries. Only `template/` is generated by the existing Copier configuration; orchestration belongs outside that subtree.

The prototype uses Python's standard library, plain JSON and SQLite. One process lock limits concurrency. Explicit checkpoints keep completed stages from repeating; uncertain interrupted work requires inspection instead of automatic replay.

Workers return closed-schema data. The coordinator owns edits, check receipts and state transitions. Builder and reviewer must use distinct identities and the same exact artifact. Source content, file modes and paths participate in the hash. Input bytes and their manifest come from one read. Each check gets a fresh verified copy.

The general Codex adapter remains closed until its execution boundary is validated. The separately authorized addition harness demonstrates two real conversations and a fixed arithmetic check. It does not prove arbitrary-project containment. No API key is created or copied; native Codex authentication is reused in place.

Git inspection rejects redirected object stores, partial clones, replacement refs, config includes, links and unsupported layouts. It checks literal object hashes and sizes, bounds output and deadlines, and cleans up its private process group. These controls are not an OS sandbox against a hostile local owner.

Improvement proposals require evidence from their own task. Existing issue codes retain their description fingerprint; conflicts fail without adding evidence. Cancellation and oversight writes are serialized. Human-approved, versioned foundation changes are separate from proposals; there is no automatic adoption API.

No background polling, billing enforcement or general production deployment is implemented. Custom runtime development is closed. The [handoff](integration-plan.md) records the unfinished connection to foundation generation and future Orca coordination; it does not install or select permissions for Orca.
